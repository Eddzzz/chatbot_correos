# Bolipost Implementation Plan

> **For agentic workers:** Use executing-plans for integration and dispatching-parallel-agents for the independent data and UI domains. Steps use checkbox syntax.

**Goal:** Deliver the approved Spanish Django postal assistant locally, with verified read-only data and OpenRouter.

**Architecture:** Django templates and JSON endpoints, SQLite for accounts and query job metadata, PostgreSQL for business data. Background query jobs spool results to private per-job SQLite files so pagination does not impose a total row cap. Demo fixtures are explicitly labeled and never substituted silently for a failed real connection.

**Tech Stack:** Python 3.12, Django 5.2 LTS, psycopg 3, sqlglot, httpx, ReportLab, Chart.js, vanilla JavaScript.

**Spec:** ../specs/2026-11-05-bolipost-design.md (approved 2026-11-05).

## Global Constraints

- Spanish UI; user/password login, browser-local per-user history.
- Business queries read only. No fixed total-row cap or 10-second PostgreSQL timeout.
- Credentials stay in ignored local configuration. No public deployment.
- All results and graphs use validated, authorized data; distinguish empty/error/unavailable.
- Existing databases and the backup must never be overwritten.

## Review Focus

- SQL aliases, functions, CTEs and forbidden fields cannot bypass the authorized views (Task 1).
- Missing DB/API credentials produce actionable errors, never fabricated responses (Tasks 2, 3).
- A user cannot page/export/cancel another user's or session's job (Task 2).
- Large results spool in batches; cancellation closes the PostgreSQL connection (Tasks 1, 2).
- Restored browser history is untrusted and cannot supply verified result values (Tasks 2, 4).

## Shared interfaces

`postal/data.py`: `get_source()` chooses explicit `DATA_MODE=demo|postgres`; source `.catalog()` returns list of `{name, columns:[{name,type,allowed}], relations:[{column,table,target}], allowed_columns:[str], queryable:bool}`. `.stream(sql, params=None, cancellation=None)` is a context manager yielding an object with `.columns:list[str]`, `.rows:Iterator[dict]`, `.sources:list[str]`. SQL uses only `assistant.<table>` authorized views. `Cancellation` exposes `.cancel()`, `.check()`, `.register(callback)` and `.cancelled`. Exceptions are `DataError(code, message)` and `QueryRejected`.

`postal/ai.py`: `plan_question(question, context, catalog) -> {sql, title, chart?, filters?}`. OpenRouter proposes SQL, never rows. Server-owned previous context is passed, not client-supplied evidence.

HTTP contracts: GET `/api/status/`; GET `/api/catalog/`; POST `/api/chat/` `{question, previous_id?}`; POST `/api/tracking/` `{code}`; POST `/api/dashboard/` `{metric}`. Creation returns `{id,status}`. GET `/api/results/<uuid>/?page=1` returns `{id,status,title,answer,columns,rows,has_more,page,source_tables,sql,filters,chart,created_at,demo,error?}`. Status is `queued|running|ok|no_matches|empty_table|error|cancelled`. POST `/api/results/<uuid>/cancel/`; GET `/api/results/<uuid>/pdf/?page=1`; POST `/accounts/logout/`. Session and CSRF required. Rows are objects keyed by column name, page size 100 is transport only. Chart uses `{kind,labels,values,label}` from verified aggregate rows, never AI-generated data.
